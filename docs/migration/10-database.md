# Supabase Postgres migration plan

Status: decision-complete. Production starts empty; **no SQLite records, showcase data, sessions, files, or backups will be imported**. The synchronous FastAPI handlers and relational transactions support SQLAlchemy 2.x, psycopg 3, and Alembic.

## 1. Target schema and SQLite mapping

Use `public`, `extensions.citext` for `COLLATE NOCASE`, `bigint GENERATED BY DEFAULT AS IDENTITY` for autoincrement keys, `boolean`, `bytea`, `jsonb`, `date`, `double precision`, and UTC `timestamptz`. Unless marked nullable, columns are NOT NULL. `created_at` and `selected_at` default to `now()`; expiry, update, and state-transition times are service-supplied. JSON defaults use `'{}'::jsonb`/`'[]'::jsonb`. Use stable constraint names for error mapping.

Each line maps a SQLite table to its target (PK is primary key; `→` is a foreign key):

- `users` → `users`: `id bigint identity PK`, `username citext UNIQUE NOT NULL`, `password_salt bytea`, `password_hash bytea`, `created_at timestamptz` (last three NOT NULL).
- `sessions` → `sessions`: `token_hash varchar(64) PK`, `username citext NOT NULL → users.username`, `created_at timestamptz NOT NULL`, `expires_at timestamptz NOT NULL`; indexes `(username)`, `(expires_at)`.
- `roles` → `roles`: `name text PK`, `description text NOT NULL`.
- `user_roles` → `user_roles`: `username citext → users.username`, `role_name text → roles.name`, composite PK `(username,role_name)`.
- `user_profiles` → `user_profiles`: `username citext PK → users.username`, `display_name text NOT NULL`, `active boolean NOT NULL DEFAULT true`, `must_change_password boolean NOT NULL DEFAULT false`, `updated_at timestamptz NOT NULL`.
- `accounts` → `accounts`: `id bigint identity PK`, `name citext UNIQUE NOT NULL`, `active boolean NOT NULL DEFAULT true`, `created_at`, `updated_at timestamptz NOT NULL`.
- `account_config` → same: `account_id bigint PK → accounts.id`; `coverage_enabled boolean DEFAULT false`, `coverage_period text DEFAULT 'week' CHECK day/week/month`, `audits_per_associate integer DEFAULT 3 CHECK >0`, nullable `identifier_column_default`, `associate_column_default text`; `exclude_previously_sampled`, `case_insensitive_ids boolean DEFAULT true`; `updated_at timestamptz`; all except nullable columns NOT NULL.
- `processes` → same: `id bigint identity PK`, `account_id bigint → accounts.id`, `name citext`, `process_type text CHECK front_office/back_office`, `timezone text DEFAULT 'local'`, `target_yield double precision DEFAULT 95 CHECK 0..100`, `target_sigma double precision DEFAULT 3 CHECK 0..6`, `active boolean DEFAULT true`, `created_at`, `updated_at timestamptz`; UNIQUE `(account_id,name)` and `(id,account_id)`.
- `process_settings` → same: `process_id bigint PK → processes.id`; `sampling_frequency text DEFAULT 'weekly' CHECK daily/weekly/monthly/manual`, `sampling_count integer DEFAULT 10 CHECK >0`, `assignment_mode text DEFAULT 'unassigned'`, `subgroup_mode text DEFAULT 'day' CHECK day/week/month`, `baseline_subgroups integer DEFAULT 20 CHECK >=5`, `critical_capa_enabled boolean DEFAULT true`, `capa_due_days integer DEFAULT 14 CHECK 1..365`, `import_mapping jsonb DEFAULT {}`, `updated_at timestamptz`; all NOT NULL.
- `app_settings` → same: `key text PK`, `value jsonb NOT NULL`, `updated_at timestamptz NOT NULL`, `updated_by citext NOT NULL → users.username`.
- `uploads` → same: `upload_id text PK`, `original_name`, `object_key`, `file_type`, `sha256 text`, `size_bytes bigint CHECK >=0`, `created_at timestamptz`, `status text DEFAULT 'READY' CHECK READY/USED/EXPIRED`; index `(status,created_at)`. `object_key` replaces local `stored_path`.
- `sampling_runs` → same: `run_id text PK`; `(process_id,account_id) bigint → processes(id,account_id)`, nullable `upload_id text → uploads.upload_id`; `source_filename`, `source_hash`, `sheet_name`, `identifier_column`, `sampling_method`, `seed`, `algorithm_version`, `app_version text`, `created_by citext → users.username`; `header_row`, `requested_count integer CHECK >0`, `eligible_count`, `selected_count integer CHECK 0<=selected_count<=eligible_count`; nullable `associate_column`, `coverage_period`, `period_key`, `void_reason text`, `voided_by citext → users.username`, `coverage_quota integer CHECK >0`, `voided_at timestamptz`; `coverage_enabled boolean DEFAULT false`; `filters jsonb DEFAULT []`, `validation`, `coverage_summary jsonb DEFAULT {}`; `created_at timestamptz`; `status text DEFAULT 'COMPLETED' CHECK COMPLETED/VOIDED`. Keep `seed` as text for manifests. Indexes `(account_id,created_at DESC)`, `(process_id,created_at DESC)`.
- `sample_records` → same: `id bigint identity PK`, `run_id text → sampling_runs.run_id`, `identifier_raw`, `normalized_identifier text`, nullable `associate`, `period_key text`, `selection_sequence integer CHECK >0`, `row_data jsonb`, `selected_at timestamptz`; required except nullable fields; UNIQUE `(run_id,selection_sequence)` and indexes `(normalized_identifier)`, `(run_id)`.
- `scorecard_versions` → same: `id bigint identity PK`, `process_id bigint → processes.id`, `name text`, `version integer CHECK >0`, `status text DEFAULT 'DRAFT' CHECK DRAFT/PUBLISHED/ARCHIVED`, `passing_score double precision DEFAULT 85 CHECK 0..100`, `opportunities_per_unit integer DEFAULT 1 CHECK >0`, `critical_fail_override boolean DEFAULT true`, `created_at timestamptz`, `created_by citext → users.username`, nullable `published_at timestamptz`; required except nullable; UNIQUE `(process_id,version)` plus partial UNIQUE `(process_id) WHERE status='PUBLISHED'`.
- `scorecard_items` → same: `id bigint identity PK`, `scorecard_version_id bigint → scorecard_versions.id`, `item_type text CHECK question/defect/sla`, `category text DEFAULT 'General'`, `name text`, `weight double precision DEFAULT 0 CHECK 0..100`, `severity text DEFAULT 'Minor'`, `critical boolean DEFAULT false`, `opportunity_count integer DEFAULT 1 CHECK >0`, nullable `target`, `lsl`, `usl double precision`, nullable `unit text`, `sort_order integer DEFAULT 0`, `active boolean DEFAULT true`; all others NOT NULL; index `(scorecard_version_id,active,sort_order)`.
- `audit_cases` → same: `audit_id text PK`, `process_id bigint → processes.id`; nullable `sample_record_id bigint → sample_records.id`, `external_case_id text`, `scorecard_version_id bigint → scorecard_versions.id`, `assigned_to`, `associate text`, `started_at/submitted_at/reviewed_at timestamptz`, `reviewed_by citext → users.username`, `rejection_reason text`, `weighted_score double precision`, `passed boolean`, `void_reason text`; `status text DEFAULT 'UNASSIGNED' CHECK UNASSIGNED/ASSIGNED/IN_PROGRESS/SUBMITTED/REVIEWED/REJECTED/VOIDED`, `source_data jsonb DEFAULT {}`, `critical_fail boolean DEFAULT false`, `opportunities integer DEFAULT 1 CHECK >0`, `defect_count integer DEFAULT 0 CHECK >=0`, `created_at timestamptz`, `created_by citext → users.username`. Partial UNIQUE `(process_id,external_case_id)` when non-null and `(sample_record_id)` when non-null; index `(process_id,status,submitted_at)`.
- `audit_responses` → same: identity `id` PK; `audit_id text → audit_cases.audit_id`, `item_id bigint → scorecard_items.id`; nullable `passed boolean`, `score`, `numeric_value double precision`, `notes text`; UNIQUE `(audit_id,item_id)`.
- `audit_defects` → same: identity `id` PK; `audit_id text → audit_cases.audit_id`, nullable `item_id bigint → scorecard_items.id`; `category`, `name`, `severity text`, `critical boolean DEFAULT false`, `opportunities integer DEFAULT 1 CHECK >0`, `created_at timestamptz`; required except `item_id`; index `(audit_id)`.
- `result_imports` → same: `import_id text PK`, `filename`, `sha256 text`, `status text DEFAULT 'PREVIEW' CHECK PREVIEW/ERROR/COMMITTED`, `columns`, `mapping jsonb` (defaults `[]`, `{}`), `row_count`, `error_count integer DEFAULT 0 CHECK >=0`, `created_by citext → users.username`, `created_at timestamptz`, nullable `committed_at timestamptz`; otherwise NOT NULL.
- `result_import_rows` → same: identity `id` PK; `import_id text → result_imports.import_id`, `row_number integer CHECK >0`, `row_data jsonb`, `status text DEFAULT 'READY' CHECK READY/VALIDATED/ERROR/COMMITTED`, nullable `error text`, `audit_id text → audit_cases.audit_id`; required unless nullable; UNIQUE `(import_id,row_number)`, index `(import_id,status)`.
- `capas` → same: `capa_id text PK`, `process_id bigint → processes.id`, nullable `audit_id text → audit_cases.audit_id`; `title text`, `priority text DEFAULT 'MEDIUM' CHECK LOW/MEDIUM/HIGH/CRITICAL`, `stage text DEFAULT 'DRAFT' CHECK` the seven `CAPA_STAGES`; nullable `owner text`, `due_date date`, `closed_at timestamptz`; `containment`, `root_cause`, `action_plan`, `implementation_notes`, `effectiveness text DEFAULT ''`; `created_at`, `updated_at timestamptz`, `created_by citext → users.username`. Partial UNIQUE `(audit_id)` when non-null; index `(process_id,stage,due_date)`.
- `capa_events` → same: identity `id` PK; `capa_id text → capas.capa_id`, `event_type text`, nullable `from_stage`, `to_stage text`, `detail jsonb DEFAULT {}`, `username citext → users.username`, `created_at timestamptz`; otherwise NOT NULL; index `(capa_id,created_at)`.
- `audit_events` → same: identity `id` PK; `event_type text`, `username citext → users.username`, nullable `entity_type`, `entity_id text`, `detail jsonb DEFAULT {}`, `created_at timestamptz`; otherwise NOT NULL; indexes `(created_at DESC)`, `(entity_type,entity_id)`.
- `schema_migrations` → Alembic-owned `alembic_version(version_num varchar(32) PK)`; do not create or copy the old table.

Deletes cascade only for users→sessions/profiles/user_roles, accounts→account_config, processes→process_settings, runs→sample records, scorecards→items, audits→responses/defects, imports→rows, and CAPAs→events. Optional provenance from runs→uploads, audits→samples, defects→items, import rows→audits, and CAPAs→audits uses `SET NULL`. All other deletes restrict; actor FKs use `ON UPDATE CASCADE`.

## 2. Data access, transactions, and compatibility

Pin compatible `SQLAlchemy>=2,<3`, `psycopg[binary]>=3,<4`, and `alembic>=1.13,<2`. `database.py` owns one process-local synchronous Engine/session factory; repositories own ORM/Core statements; services own one `Session.begin()` unit of work. Routes retain current paths, request/response shapes, statuses, and details. Mutations write `audit_events` in the same transaction. Storage deletion and backup execution use `StorageService`/`BackupService` after commit, outside repositories.

Internal changes are exact: `connect()`/`db()` become `get_session()`/`unit_of_work()`; helpers accept `Session`; `sqlite3.Row` and positional access become typed models or `result.mappings()`; `dict(row)` becomes DTO mapping; JSON strings become dict/list values and serialize identically at HTTP; booleans become `bool`; timestamps become aware UTC `datetime` but DTOs emit existing ISO strings. Rename `stored_path`, `row_json`, `source_json`, `*_json` attributes to `object_key`, `row_data`, `source_data`, and the JSON names above. No persistence object crosses the service boundary.

Replace `?` SQL with SQLAlchemy expressions (or named `:param` text); dynamic `IN` lists use expanding bind parameters. Replace `INSERT OR IGNORE` with PostgreSQL `ON CONFLICT DO NOTHING`, existing upserts with `on_conflict_do_update()`, and `lastrowid` with `INSERT ... RETURNING`. Replace `PRAGMA table_info`/`sqlite_master` with Alembic metadata and SQLAlchemy Inspector only in tests/tools. Remove foreign-key/WAL PRAGMAs, `executescript`, startup DDL, and WAL setup.

Replace `sqlite3.IntegrityError` with SQLAlchemy `IntegrityError` mapped by constraint/SQLSTATE: unique `23505`→409 with current detail; FK `23503`→404 for missing references or 409 for blocked deletion; check/not-null/data `23514`/`23502`/class `22`→400. Stale transitions→409; connectivity/pool/lock/statement timeout→503; unknown failures→500 with correlation ID, never SQL/secrets. Roll back before mapping.

Use READ COMMITTED plus targeted locks: advisory lock for first-admin; lock process before allocating `MAX(version)+1` and publishing; lock upload/process while rechecking sampling eligibility; lock audit/import/CAPA for transitions. Unique indexes arbitrate duplicate accounts, external cases, published cards, and CAPAs. Retry deadlock/serialization at most twice only for idempotent commands; non-idempotent commands use existing generated IDs and return 409 on a competing commit.

## 3. Connections and secrets

`DATABASE_URL` is `postgresql+psycopg://...` using Supabase's **session pooler** (IPv4, port 5432) for the persistent Render service. Start with one web worker, SQLAlchemy `pool_size=5`, `max_overflow=0`, `pool_timeout=10`, `pool_recycle=300`, and `pool_pre_ping=True`; total pools across workers must stay within the Supavisor allocation. `DIRECT_DATABASE_URL` uses the direct database endpoint on port 5432 and is available only to the migration/backup job, whose runner must have IPv6 reachability (or the Supabase IPv4 option). Alembic must never use the runtime pooler URL. Supabase documents these connection roles [here](https://supabase.com/docs/guides/database/connecting-to-postgres).

Enforce server-side SSL. Both URLs use `sslmode=verify-full` and a secret-mounted CA via `sslrootcert`; `require` is emergency-only because it does not verify hostname ([SSL guidance](https://supabase.com/docs/guides/platform/ssl-enforcement)). Keep URLs, CA, password, and bootstrap credentials only in scoped Render/CI secrets—never committed `.env`, Alembic config, logs, frontend variables, or errors. Percent-encode credentials, separate least-privilege runtime/migration roles, rotate on access changes, and redact parameters/URLs.

## 4. Creation, bootstrap, revisions, and deployment

Create `0001_postgres_schema` (extension, tables/checks/FKs/indexes) and `0002_seed_roles` (four `ROLES`, idempotent by PK). Thereafter use one logical change per reviewed revision, deterministic upgrade/downgrade, no runtime DDL, and no SQLite branches. CI runs `upgrade head` on empty Postgres, compares metadata, and proves a second upgrade is a no-op. Readiness fails unless the database is at head.

Before public traffic, a one-shot CLI reads the password from stdin and uses the runtime hasher. One advisory-locked transaction verifies zero users, inserts `admin`, profile, Administrator role, and audit event; credentials are not logged and must change at first login. `/api/setup` is not publicly exposed before this; afterward it retains the current 409. No default password or showcase seed exists.

Deployment: provision project/roles/SSL/CA; keep Render private; inject secrets; run `alembic upgrade head` via the direct URL; run first-admin CLI; start on the pooler; check revision/readiness/login/core writes; expose traffic. Roll back code only to a schema-compatible release; forward-fix schema by default and downgrade only after a rehearsed backup/restore decision.

Remove SQLite `Connection.backup`, integrity PRAGMA, startup backup, and live replacement. Existing backup routes/JSON keys remain adapters; `BackupService` invokes an isolated privileged `pg_dump`/`pg_restore` job through `DIRECT_DATABASE_URL`, encrypted private storage, checksum plus `pg_restore --list` validation, retention, and maintenance-window restores. Reject SQLite content—there is no import path—and keep restore credentials out of the web process.

## 5. Test conversion and release gates

Replace `QSR_DATA_DIR` SQLite fixtures and table-delete setup with a disposable Postgres database: apply Alembic once, seed reference roles, and wrap each test in an outer transaction plus nested savepoint; factories create admin/account/process data. Replace raw `?`, `lastrowid`, integer booleans, JSON text, timestamp strings, and `sqlite_master` assertions with repository calls, `RETURNING`, typed values, and Inspector/Alembic-head assertions. Keep all eight current behavioral tests unchanged at the HTTP/service assertion level.

CI integration tests run real Postgres and cover empty `upgrade head`, defaults/checks/FKs/cascades, case-insensitive uniqueness, JSON/timestamp round trips, constraint-to-HTTP errors, rollback of failed imports, and backup adapter isolation. Concurrent two-connection tests cover setup, duplicate account, scorecard version/publish, same import commit, same audit review/CAPA, upload consumption, and prior-sample exclusion; assert one committed result, no duplicates, and deterministic 409/idempotent outcome. A release-gated disposable Supabase smoke test separately exercises the session-pooler runtime URL, direct migration URL, SSL verification, pool exhaustion/timeout, and reconnect after idle restart; never target production.
